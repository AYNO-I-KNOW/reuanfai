# ADR-0016: รับ design รอบ 2 จาก `thanid-design` — ติดต่อด่วนในหัวหน้าแรก/แชท, หน้าโปรไฟล์, บันทึกอาการ, คำถามแนะนำในแชท

- สถานะ: Accepted · 2026-10-27 · ตัดสินโดยเจ้าของโปรเจกต์ (เกรพ) สั่งให้รับ design รอบ 2 ที่ merge จาก branch `thanid-design` (`7f38980`) และแก้จุดที่ขัดกฎ · ที่มา: `apps/web/src/app/ruenfai/**` (EmergencyAction, profile, JournalForm, chat-topics, ChatInvitation, BottomNav, AppointmentSheet, EntryGate) · แก้เพิ่ม ADR-0014 (ข้อ 1 alias `profile`, ข้อ 5 journal) และ ADR-0015 (ข้อ 3 ตำแหน่งติดต่อด่วน + ผลที่ตามมาเรื่องกด 2 ครั้ง/เบอร์ 2 แหล่ง) เฉพาะส่วนที่ระบุในตาราง "ส่วนที่เปลี่ยน"

## บริบท
design รอบ 2 เปลี่ยนสิ่งที่ ADR-0014/0015 และ screen-map บันทึกไว้ ตรวจจากโค้ดหลัง merge แล้ว:
- ติดต่อด่วน (M12) เป็น component `EmergencyAction` อยู่ในหัวหน้าแรก (ปุ่ม "ฉุกเฉิน") และหัวแชท (ไอคอน) · เปิด sheet ที่มี โทร 1669, โทรผู้ติดต่อฉุกเฉิน, เลือกผู้ป่วย (คุณแม่/ลูกน้อย), สถานที่ + พิกัด, อาการ และข้อความแจ้งเหตุให้คัดลอก/แชร์เอง
- `ruenfai/profile` เป็นหน้าดู/แก้ข้อมูลคุณแม่จริง ไม่ใช่ alias ของ appointments อีกต่อไป
- journal มีชิปอาการ (เลือกได้หลายข้อ) และข้อความไม่บังคับ
- แชทมี quick prompt ตามช่วงหลังคลอด และ bubble คำถามแนะนำ (`ChatInvitation`) เหนือ bottom nav
- bottom nav ปุ่มกลาง "เขียนบันทึกประจำวัน" · การ์ดนัดที่จองแล้วกดเปิดรายละเอียดนัด
- จุดที่ขัดกฎและแก้ใน merge นี้: ปุ่มติดต่อด่วนเล็กกว่า 48px · หน้าโปรไฟล์ไม่บังคับเบอร์ และ `pattern` พังใน Chrome (regex v-flag) · ไม่มีข้อความว่าแก้วันคลอดแล้วจะคำนวณใหม่ · dialog อ่านเบอร์ฉุกเฉินจาก localStorage แยกจากโปรไฟล์ แก้ที่โปรไฟล์แล้วไม่มีผล · splash ค้างได้ถ้ารูป decode ไม่จบ

CLAUDE.md กฎข้อ 1 (ADR-0000) ให้เปลี่ยนด้วย ADR ใหม่ จึงออก ADR นี้ supersede เฉพาะส่วนที่ขัดกัน ส่วนที่ไม่ได้ระบุไว้ที่นี่ไม่เปลี่ยน

## ตัดสินใจ
1. **ติดต่อด่วน (M12)**: อยู่ใน**หัวหน้าแรก** (`ruenfai`) และ**หัวแชท** (`ruenfai/chat`) · จากหน้าแรกกดครั้งเดียว · route `ruenfai/emergency` คงไว้ (เข้าจาก `refer`)
   - ปุ่มเปิด sheet ต้องมีพื้นที่กด ≥ 48×48px (DESIGN-REVIEW §1)
   - คงข้อกำหนด ADR-0014 ข้อ 6 / ADR-0015 ข้อ 3: โทร 1669 + โทร `emergencyPhone` · ลิงก์ `tel:` ใช้ได้ทันที ไม่ต้องรอ api/auth
   - เบอร์ผู้ติดต่อฉุกเฉินอ่านจากแหล่งเดียว คือ profile แม่ (พรีวิว: `motherProfile` `reuanfai-mother-profile-v1`; จริง: `GET /me`) · key เดิม `ruenfai-emergency-phone` อ่านเฉพาะตอน profile ยังไม่มีเบอร์ แล้วย้ายเข้า profile และลบ key เดิม
   - ข้อความแจ้งเหตุที่ผู้ใช้**คัดลอก/แชร์เอง**มี: ผู้ป่วย (คุณแม่ + จำนวนวันหลังคลอด + วิธีคลอด หรือ ลูกน้อย), อาการที่พิมพ์, สถานที่, พิกัด, เบอร์ติดต่อกลับ (`phone`) · ระบบไม่ส่ง ไม่บันทึก และไม่ส่งต่อข้อความนี้
   - ขอตำแหน่ง (geolocation) **เฉพาะเมื่อผู้ใช้เปิด sheet** หรือกด "ใช้ตำแหน่งปัจจุบัน/อัปเดตพิกัด" · ห้ามขอตอนโหลดหน้า · ลิงก์ "ดูใน Google Maps" เปิดเมื่อผู้ใช้กด พร้อมบอกว่าจะแชร์พิกัดกับ Google
   - **ADR-0006 ใช้กับข้อความที่ระบบส่ง** (LINE notify/outbox) · การคัดลอก/แชร์โดยผู้ใช้ผ่าน clipboard หรือ share sheet ของเครื่องเป็นการเลือกของผู้ใช้ ไม่ใช่ข้อความที่ระบบส่ง จึงไม่ขัด ADR-0006 · ความเสี่ยงที่เหลือ (ข้อมูลสุขภาพ + ตำแหน่งไปอยู่ในแชทกลุ่ม/แอปอื่น) = SPEC Q27
2. **หน้าโปรไฟล์ (`ruenfai/profile`)**: เป็นหน้าดู + แก้ข้อมูลคุณแม่ (M2 โหมดแก้ไข) เข้าจากรูปโปรไฟล์ในหัวหน้าแรก · ซ่อน bottom nav
   - `phone`, `emergencyPhone`, `deliveryDate`, `birth` เก็บใน `motherProfile` · ชื่อ, โรคประจำตัว, ประวัติแพ้ยา, ชื่อ/ความสัมพันธ์ผู้ติดต่อ เก็บใน localStorage `ruenfai-profile-details-v1` (ข้อมูลจำลองเท่านั้น — ADR-0012) · ก่อนมีข้อมูลจริงต้องย้ายไป `PUT /me/profile` (ADR-0004)
   - `phone` + `emergencyPhone` **บังคับ** และตรวจด้วยกฎเดียวกับ onboarding (ขึ้นต้น 0 ยาว 9–10 หลัก) (ADR-0014 ข้อ 6)
   - แก้วันคลอดแล้วต้องแสดงว่า "ผลการประเมินจะคำนวณใหม่" (screen-map M2) · พรีวิวไม่คำนวณเอง (ADR-0001) การคำนวณใหม่จริงเป็นของ api ตาม ARCHITECTURE §4
   - โรคประจำตัว/แพ้ยาในหน้านี้เป็นข้อความอิสระ ต่างจาก M2 onboarding ที่เป็นตัวเลือก (`chronic[]`, `herbalAllergy`) → SPEC Q20
3. **Journal (M13)**: บังคับแค่อารมณ์ · ชิปอาการ (พักผ่อนน้อย, เจ็บแผล, คัดตึงเต้านม, ปวดเมื่อย) เลือกได้หลายข้อ ไม่บังคับ · ข้อความไม่บังคับ · อาการเป็นข้อมูลสุขภาพ ห้ามอยู่ในข้อความ LINE (ADR-0006) · consent/การแชร์ยังเป็น SPEC Q11
4. **แชทผู้ช่วย (M14)**: quick prompt เลือกตามช่วงหลังคลอด (≤7, ≤14, ≤42, >42 วัน) + มีนัดที่จะถึง + ผ่าคลอด + "มีเรื่องยาอยากถาม?" + "วันนี้รู้สึกอย่างไร?" · `ChatInvitation` แสดงคำถามแนะนำเหนือ bottom nav กดแล้วเปิดแชทพร้อมเติมคำถามในช่องพิมพ์ (ไม่ส่งเอง) · ยังตอบข้อความตายตัว ไม่มี AI · ข้อจำกัด ADR-0015 ข้อ 1 ใช้กับทุก prompt
5. **Bottom nav**: 4 tab (หน้าแรก, นัดหมาย, ยา, บันทึก) + ปุ่มกลาง "เขียนบันทึกประจำวัน" (เปิด dialog เขียนบันทึก) + ปุ่มแชทแยกด้านขวา · ไม่มีปุ่มติดต่อด่วน (ข้อ 1)
6. **การ์ดนัดที่จองแล้ว (M7)** และรายการนัดในหน้าแรกกดเปิด `AppointmentSheet` ("รายละเอียดนัดหมาย": วันที่, เวลา, สถานที่, ผู้ให้บริการ) แบบอ่านอย่างเดียว · ไม่เปลี่ยน state machine ของนัด
7. **Splash (`EntryGate`)**: แสดงอย่างน้อย 3 วินาที รอฟอนต์ + รูปที่เห็นบนจอ แต่รอไม่เกิน 5 วินาที รูปที่ค้างต้องไม่ทำให้เข้าแอปไม่ได้

## ส่วนที่เปลี่ยน
| ที่มา | ส่วนที่ supersede | เปลี่ยนเป็น |
|---|---|---|
| ADR-0014 | ข้อ 1: "`profile` เป็น alias ของ prototype ไม่ใช่ feature" | `ruenfai/profile` = M2 โหมดแก้ไข (ข้อ 2) · `growth`, `baby` ยังเป็น alias |
| ADR-0014 | ข้อ 5: journal "อารมณ์ 5 ระดับ + ข้อความ" | อารมณ์ (บังคับ) + ชิปอาการ + ข้อความ (ไม่บังคับ) (ข้อ 3) |
| ADR-0015 | ข้อ 3: ติดต่อด่วน = dialog ในหัวแชท + route · ผลที่ตามมา: "จาก tab กด 2 ครั้ง", "ผู้ติดต่อฉุกเฉินมี 2 แหล่งในพรีวิว" | หัวหน้าแรก + หัวแชท + route · จากหน้าแรกกดครั้งเดียว · เบอร์แหล่งเดียว (ข้อ 1) |
| ADR-0015 | บริบท: quick prompt 3 ข้อ ("การดูแลหลังคลอด", "สอบถามเรื่องยา", "เตรียมตัวไปตามนัด") | quick prompt ตามช่วงหลังคลอด + `ChatInvitation` (ข้อ 4) |
| DESIGN-REVIEW §1 | "ปุ่มติดต่อด่วนใน bottom nav เปิด sheet สูง ≥ 48px" | ปุ่มในหัวหน้าแรก/หัวแชท พื้นที่กด ≥ 48×48px (ข้อ 1) |

## ไม่เปลี่ยน
- ADR-0001: engine pure/deterministic ไม่มี LLM/I/O · web ไม่คำนวณผลเอง · ADR-0005: `unsure` ไม่ถือเป็นผ่าน
- ADR-0004: web ไม่ต่อ DB ตรง · ADR-0006: ไม่มีข้อมูลสุขภาพในข้อความที่ระบบส่งทาง LINE · ADR-0007: consent 2 ชั้น · ADR-0008: กรมฯ ใช้ `agg_*` + n<5
- ADR-0012: ข้อมูลจำลองเท่านั้น · ADR-0015 ข้อ 1 (แชทไม่มี AI, ห้ามแนะนำยารายบุคคล), ข้อ 2 (ชำระเงินสาธิต + ข้อความ "รายการสาธิต · ยังไม่มีการเรียกเก็บเงินจริง"), ข้อ 4
- การรับ design ตาม ADR นี้**ไม่ใช่การผ่าน `DESIGN-REVIEW.md`** — CLAUDE.md กฎข้อ 2 ยังใช้ต่อ phase

## ผลที่ตามมา
- ติดต่อด่วนจากหน้าแรกกด 1 ครั้ง · จาก tab อื่นต้องกลับหน้าแรกหรือเข้าแชทก่อน (2 ครั้ง) · onboarding, review, payment, profile ไม่มีทางเข้า → ยังต้องตัดสินใน DESIGN-REVIEW (SPEC Q25)
- ข้อความแจ้งเหตุมีข้อมูลสุขภาพ + ตำแหน่ง + เบอร์ ออกจากระบบผ่านผู้ใช้ → ต้องตัดสินว่าต้องเตือน/ตัดข้อมูลบางส่วนก่อนแชร์ไหม (SPEC Q27)
- `ruenfai-profile-details-v1` เก็บโรคประจำตัว/แพ้ยาใน localStorage — ยอมรับได้เฉพาะข้อมูลจำลอง (ADR-0012) เหมือน `reuanfai-care-journey-v1` (SPEC Q24) · ต้องรวมกับ M2 ตอนต่อ api (SPEC Q20)
- `api.md` / `data-model.md` ยังไม่มีชื่อผู้ติดต่อ, ความสัมพันธ์, symptoms ของ journal → ต้องแก้ spec ก่อนทำ API ไม่เพิ่ม schema จาก UI เอง
