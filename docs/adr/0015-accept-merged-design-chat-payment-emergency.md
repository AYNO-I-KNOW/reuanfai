## บริบท
design รอบที่ merge เพิ่ม/เปลี่ยนสิ่งที่ spec และ ADR-0014 ไม่ได้ครอบคลุม ตรวจจากโค้ดแล้ว:
- `ruenfai/chat` — หน้าแชท "ผู้ช่วยส่วนตัว" เข้าจากปุ่มขวาสุดของ bottom nav (aria-label "สนทนากับผู้ช่วย AI") · **ไม่มีการเรียก AI/LLM/API** ตอบด้วยข้อความตายตัวชุดเดียว (หน่วงเวลา 1.2 วินาที) ไม่ว่าถามอะไร · quick prompt: "การดูแลหลังคลอด", "สอบถามเรื่องยา", "เตรียมตัวไปตามนัด" · ข้อความเก็บใน React state ไม่บันทึกที่ใด · bottom nav ซ่อนในหน้านี้
- `ruenfai/payment` — หน้า "สรุปค่าใช้จ่าย" เข้าจากการ์ดนัดหมาย (`/ruenfai/payment?appointment=<id>`) · ราคาตายตัว (ค่าบริการ 300 + ยา 80 + 120) · 3 วิธี (QR พร้อมเพย์ / บัตร / เงินสด) ไม่เชื่อมระบบชำระเงิน · มีข้อความ "สาธิต · ยังไม่มีการเรียกเก็บเงินจริง" · บันทึก "จ่ายแล้ว" ใน `sessionStorage` `ruenfai-payment-ui-v1` · bottom nav ซ่อนในหน้านี้
- ติดต่อด่วน (M12) — เดิมเป็น dialog ใน bottom nav (ทุก tab กดครั้งเดียว) ตอนนี้ปุ่มนั้นกลายเป็นปุ่มเข้าแชท · ช่องทางติดต่อด่วนที่เหลือ: (1) dialog ในหัวหน้าแชท (ไอคอนโทรศัพท์ → `tel:1669` + โทรผู้ติดต่อฉุกเฉิน) (2) route `ruenfai/emergency` (`tel:1669`, ผู้ติดต่อฉุกเฉิน, รายการ 7 อาการ, ข้อความ "ยังไม่มีเบอร์หน่วยบริการ") ซึ่งไม่มีลิงก์จาก bottom nav/แชท — เข้าได้จาก `ruenfai/refer` เท่านั้น (ตรวจโค้ด ณ 2026-10-26)
- เอกสารปัจจุบันขัดกัน: ADR-0014 ข้อ 6 / screen-map M12 / ARCHITECTURE §3 ว่าเป็น sheet ใน bottom nav ไม่มี route · SPEC §7 ว่าชำระเงินนอกขอบเขต · data-model ไม่มี entity การชำระเงิน · ADR-0009 จำกัด AI เหลือ AI-1/AI-2

เจ้าของโปรเจกต์สั่งรับ design ตามที่ merge CLAUDE.md กฎข้อ 1 (ADR-0000) ให้เปลี่ยนด้วย ADR ใหม่ จึงออก ADR นี้ supersede เฉพาะส่วนที่ขัดกัน ส่วนที่ไม่ได้ระบุไว้ที่นี่ไม่เปลี่ยน

## ตัดสินใจ
1. **แชทผู้ช่วย (`ruenfai/chat`)**: อนุญาตเป็น UI ที่มี**เนื้อหาตายตัว/สาธิตเท่านั้น** (ข้อมูลจำลอง — ADR-0012)
   - ห้ามต่อ LLM/AI ใด ๆ เข้าหน้านี้ภายใต้ ADR นี้ · ถ้าจะทำ AI จริง ต้องอยู่ในขอบเขต ADR-0009 (AI-1/AI-2) หรือเขียน ADR ใหม่ (ดู SPEC Q21) · ADR-0001 ยังใช้: AI ไม่ตัดสินผลคัดกรอง/สิทธิ์/ข้อห้ามยา
   - เนื้อหาในแชท (ไม่ว่าตายตัวหรือในอนาคต) **ห้ามแนะนำยาหรือหัตถการรายบุคคล และห้ามวินิจฉัย** (SPEC §7) · quick prompt "สอบถามเรื่องยา" ต้องตอบได้แค่ข้อมูลทั่วไป + ชี้ให้ถามแพทย์แผนไทย/หน่วยบริการ · ห้ามบอกว่ายาตัวไหนกินได้/ไม่ได้สำหรับแม่คนนั้น · ห้ามใช้คำว่า "ปลอดภัย" (ADR-0005)
   - ปุ่มเข้าแชทใช้ aria-label "สนทนากับผู้ช่วย AI" แต่ยังไม่มี AI — ป้ายนี้ต้องตรงความจริงก่อนใช้งานจริง (ดู SPEC Q21)
   - ข้อความแชทที่ผู้ใช้พิมพ์เป็นข้อมูลสุขภาพได้ → ถ้าจะบันทึก/ส่งต่อ ต้องผ่าน api (ADR-0004) + consent (ADR-0007) และห้ามอยู่ในข้อความ LINE (ADR-0006) · ปัจจุบันไม่บันทึก
2. **หน้าชำระเงิน (`ruenfai/payment`)**: อนุญาตเป็น **UI สาธิตเท่านั้น**
   - ห้ามเรียกเก็บเงินจริง ห้ามเชื่อมผู้ให้บริการชำระเงิน/สปสช./e-Claim ใด ๆ (ADR-0012) · ราคาและรายการยาเป็นข้อมูลจำลอง · ต้องคงข้อความ "สาธิต · ยังไม่มีการเรียกเก็บเงินจริง" บนหน้า
   - ไม่เพิ่ม entity/endpoint การชำระเงินใน data-model/api.md · สถานะ "จ่ายแล้ว" เป็นของ UI เท่านั้น ไม่มีผลต่อ `appointments` state machine, quota หรือสิทธิ์
   - ชำระเงินจริงยังนอกขอบเขต (SPEC §7) จนกว่าเจ้าของจะสั่งเป็น ADR ใหม่ (SPEC Q22)
3. **ติดต่อด่วน (M12)**: ย้ายจาก "sheet ใน bottom nav ไม่มี route" เป็น
   - dialog ในหัวหน้าแชท (`ruenfai/chat`) + route `ruenfai/emergency` · ปุ่มติดต่อด่วนออกจาก bottom nav
   - ข้อกำหนดเดิมของ ADR-0014 ข้อ 6 ที่ยังใช้: โทร 1669 + โทร `emergencyPhone` · รายการ 7 อาการไม่บังคับ · ใช้ได้ทันที ไม่ต้องรอ api/auth (เป็นลิงก์ `tel:` ตรง) · `phone`/`emergencyPhone` บังคับใน M2
   - รายละเอียด UX ที่ design ส่งมา (ไอคอนโทรศัพท์ในหัวแชท, route ที่เข้าจาก refer) ถือเป็น design ที่อนุมัติแล้ว แต่ยังต้องผ่าน `DESIGN-REVIEW.md`
4. **หน้าที่ implement ไปแล้วโดยยังไม่มีรายการใน design handoff เดิม** — `ruenfai/refer` (M4-R), `ruenfai/checkin` (M8), `ruenfai/sharing` (M11): รับเข้า spec เป็นหน้าสาธิต (ข้อมูลจำลอง) · route ของ M8 เป็น `ruenfai/checkin` (หน้าเดียว เลือกนัดจาก dropdown) แทน `checkin/[id]` · ผลเช็กอินในพรีวิวเป็น `awaiting_eval` เสมอ เพราะ web ห้ามคำนวณผลเอง (ADR-0001) ต้องรอ api + rules engine (SPEC Q23) · `ruenfai/sharing` และ `ruenfai/checkin` ยังไม่มีลิงก์เข้าจากหน้าใด (SPEC Q26) · ทั้งสามหน้ายังไม่ผ่าน design review

## ไม่เปลี่ยน
- ADR-0001: engine pure/deterministic ไม่มี LLM/I/O · ADR-0005: `unsure` ไม่ถือเป็นผ่าน · ห้ามคำว่า "ปลอดภัย"
- ADR-0004: web ไม่ต่อ DB ตรง · ADR-0006: ไม่มีข้อมูลสุขภาพในข้อความ LINE · ADR-0007: consent 2 ชั้น · ADR-0008: กรมฯ ใช้ `agg_*` + n<5
- ADR-0009 ขอบเขต AI-1/AI-2 และป้าย "ข้อเสนอจาก AI" / "สรุปโดย AI"
- ADR-0012: ข้อมูลจำลองเท่านั้น ไม่เชื่อมระบบจริง
- ADR-0014 ส่วนอื่นทั้งหมด · SPEC §7 ข้ออื่น (วินิจฉัยโรค, แนะนำยา/หัตถการรายบุคคล, เชื่อมระบบจริง ฯลฯ)
- การรับ design ตาม ADR นี้**ไม่ใช่การผ่าน `DESIGN-REVIEW.md`** — CLAUDE.md กฎข้อ 2 ยังใช้ต่อ phase

## ผลที่ตามมา
- ติดต่อด่วนจาก tab ใด ๆ ต้องกด 2 ครั้ง (ปุ่มแชท → ไอคอนโทรศัพท์หัวแชท) เดิม 1 ครั้ง · หน้า onboarding, review, payment ไม่มีทางเข้า (ซ่อน bottom nav; onboarding/review เดิมก็ไม่มี) · ต้องให้ DESIGN-REVIEW ตัดสินว่ารับได้ไหม เพราะ UX brief ล็อกให้ติดต่อด่วนเข้าถึงได้ทุกหน้า (ถูก supersede บางส่วนโดย ADR-0014 แล้ว)
- ผู้ติดต่อฉุกเฉินมี 2 แหล่งในพรีวิว: dialog หัวแชทอ่าน localStorage `ruenfai-emergency-phone`, หน้า `ruenfai/emergency` อ่าน `motherProfile` (`reuanfai-mother-profile-v1`) · ต้องรวมเป็น `GET /me` (`emergencyPhone`) ตอนต่อ api
- แชทตอบข้อความตายตัวชุดเดียวทุกคำถาม รวมถึง "สอบถามเรื่องยา" — ยังไม่มีเนื้อหาที่ต้องตรวจตามข้อ 1 · ก่อนเพิ่มเนื้อหา/AI ต้องผ่านข้อจำกัดข้อ 1
- ข้อมูลสุขภาพจำลอง (ความปวด คำตอบเช็กอิน ผล, consent/แชร์, สถานะส่งต่อ) อยู่ใน localStorage `reuanfai-care-journey-v1` (`apps/web/src/design/care-journey.ts`) — ยอมรับได้เฉพาะข้อมูลจำลอง (ADR-0012) · ก่อนมีข้อมูลจริงต้องย้ายไป api + auth (ADR-0004/0006/0011) (SPEC Q24)
- หน้าที่ implement ก่อนผ่าน design review (CLAUDE.md กฎข้อ 2) ต้องผ่าน review ก่อนถือเป็นงานของ phase (SPEC Q25)
- `ruenfai/sharing` ไม่มีทางเข้า (ถอน consent/ลบข้อมูลเข้าไม่ถึง) · `ruenfai/checkin` ไม่มีลิงก์เข้าจากหน้านัดหมาย/แจ้งเตือน · `ruenfai/refer` เข้าจากการ์ดนัดหมายเมื่อ `referralLocked` ส่วนผลเช็กอิน `referred` ที่ชี้มาหน้านี้พรีวิวไม่เคยสร้าง · `ruenfai/emergency` เข้าได้จาก `refer` เท่านั้น → ต้องเพิ่ม entry point หรือตัดสินใจ (SPEC Q26)
