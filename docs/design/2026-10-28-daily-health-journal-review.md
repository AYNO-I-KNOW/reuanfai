## ประเด็นจาก requirement และข้อเสนอ

### Mood

คงหน้าอีโมจิกลมเดิม/มีสีหน้าต่างกัน แต่ต้องตัดสินความหมายของ5ระดับก่อน ปัจจุบัน “เหนื่อย” เป็นอาการ/พลังงาน ส่วน “เครียด” เป็นความรู้สึก จึงไม่ควรแปลง1–5เป็นคะแนนสุขภาพจิตโดยปริยาย

เสนอชุดภาษาที่เป็นแนวเดียวกัน เช่น ไม่สบายใจมาก / ไม่ค่อยสบายใจ / เฉยๆ / สบายใจ / สบายใจมาก โดยความเหนื่อยและโกรธอาจเป็นรายละเอียดอารมณ์แยกในภายหลัง สีแดงอมส้มสำหรับโกรธต้องไม่สับสนกับกล่องแจ้งเตือนทางการแพทย์ และไม่อนุมานว่าผู้เลือกสีแดงอยู่ในภาวะอันตราย

### ความปวด

- ถาม “วันนี้ปวดมากที่สุดระดับใด” 0–10 พร้อมคำอธิบายปลายสเกล 0=ไม่ปวด,10=ปวดมากที่สุด และแสดงตัวเลขที่เลือกชัดเจน
- แยกตำแหน่ง แผลฝีเย็บ/แผลผ่าคลอด/ท้องน้อย/เต้านม/หลัง
- ต้องชัดว่าคะแนนเดียวอ้างถึงตำแหน่งที่ปวดมากที่สุด หรือเก็บคะแนนต่อตำแหน่ง หากทำเลือกหลายตำแหน่งกับคะแนนเดียวต้องไม่ทำให้รายงานตีความผิด
- เมื่อ0ซ่อน/ล้างตำแหน่งตามกติกาที่ตกลง ไม่ตีความไม่ตอบเป็น0

### น้ำคาวปลา

- แยกคำถามปริมาณ สี กลิ่น และลิ่มเลือด ไม่รวมเป็น choiceก้อนเดียว
- ปริมาณตามรายการผู้ใช้และเพิ่ม ไม่มีน้ำคาวปลา/ไม่แน่ใจ เพื่อหลีกเลี่ยงบังคับข้อมูลที่ไม่ตรงจริง คำว่า “ปกติ/มาก” ต้องมีตัวอย่างหรือคำอธิบายที่ทีมคลินิกรับรอง
- สีเป็น swatch/illustrationพร้อมชื่อ แดงสด/ชมพู–น้ำตาล/เหลือง–ขาว ไม่ใช้สีอย่างเดียวหรือภาพเลือดสมจริง
- กลิ่นเหม็นและลิ่มเลือดใช้ใช่/ไม่ใช่/ไม่แน่ใจแยกกัน ภาษาขนาดไข่ไก่หรือใหญ่กว่าต้องให้ทีมคลินิกยืนยันตรงเกณฑ์ (CDCใช้ bigger than an egg)

### ไข้

อาการตัวร้อน/หนาวสั่นและค่าอุณหภูมิไม่ควรเป็น radioสามตัวที่เลือกได้เพียงอย่างเดียว เพราะมีอาการและวัดได้พร้อมกันได้ เสนอให้เลือกอาการก่อน มีช่อง “อุณหภูมิที่วัดได้” แยกพร้อม °C และสถานะ ยังไม่ได้วัด ค่าไม่ตอบไม่ใช่ไม่มีไข้

### แผล

เปลี่ยนหัวข้อเป็นแผลฝีเย็บ/แผลผ่าคลอดตามข้อมูลที่มีจริง ไม่ถือว่าคลอดทางช่องคลอดทุกคนมีแผลฝีเย็บ ถ้าไม่ทราบหรือไม่มีแผลควรมีตัวเลือกตรงจริง

บวมแดง/มีหนองหรือน้ำซึม/แผลแยกอาจพบพร้อมกัน จึงเสนอเลือกหลายข้อ โดย ไม่มีอาการผิดปกติ และ ไม่มีแผล เป็น mutually exclusive กับอาการ ทีมคลินิกยืนยันถ้อยคำและการจัดกลุ่มก่อนทำ production

### เต้านม

อาการคัดตึง/ก้อนแดงเจ็บ/หัวนมแตกอาจอยู่พร้อมกัน ใช้หลายตัวเลือก โดยไม่มีอาการผิดปกติแยกจากอาการ เพิ่มข้างซ้าย/ขวา/ทั้งสองข้างเมื่อมีอาการหากทีมต้องใช้ข้อมูลนั้น ไม่ใช้ตัวเลือกเดียวที่บังคับกลบอาการอื่น

### Note

คงช่องข้อความท้ายสุด ใช้คำ “บันทึกเพิ่มเติม” placeholder “ระบุอาการหรือเรื่องที่ต้องการบันทึกเพิ่มเติม” ไม่ซ้ำ textarea เรื่องราวอีกช่องในฟอร์มเดียว ข้อความเดิมใน bodyต้องยังอ่าน/แก้ได้

## โครงหน้าที่เสนอ

ใช้ sheetขยายเต็มความสูงและเนื้อหาเลื่อน พร้อมวันที่/ปิดด้านบนและบันทึก fixedด้านล่าง คง7กลุ่มตามลำดับ: อารมณ์ → ความปวด → น้ำคาวปลา → ไข้ → แผล → เต้านม → บันทึกเพิ่มเติม เผยรายละเอียดตามคำตอบ เช่นเลือกวัดแล้วจึงเปิดช่ององศา ไม่ทำทุกฟิลด์ซ้อนเป็น sheetหลายชั้น

ช่องที่ยังไม่ตอบต้องระบุเป็น missing/ไม่ได้ระบุ ไม่ตั้งค่าเริ่มต้นว่าไม่มีอาการหรือปกติ ไม่ใช้ความครบของรายงานเป็นหลักฐานว่าไม่มีความเสี่ยง กติกาว่าข้อไหน requiredต้องตกลงก่อน และไม่ลบทางขอความช่วยเหลือเมื่อformยังกรอกไม่ครบ

หลังบันทึก readerต้องเป็นสรุปข้อมูลแต่ละกลุ่ม+note ไม่ใช่ข้อความยาวอย่างเดียว; ปฏิทินยังใช้moodเป็นภาพประจำวันโดยไม่แปลงวงกลมให้เป็นผลคัดกรองทางการแพทย์

## อาการเตือนและขอบเขต

CDCระบุไข้38°Cขึ้นไป เลือดชุ่มผ้าอนามัยตั้งแต่หนึ่งแผ่นใน1ชั่วโมง ลิ่มเลือดใหญ่กว่าไข่ หรือสิ่งคัดหลั่งมีกลิ่นเหม็นเป็นสัญญาณเตือนที่ควรได้รับการดูแลทันที ไม่ควรให้ flowจบเพียงบันทึกสำเร็จ/รอแชต

เสนอให้ทีมคลินิกกำหนด copy/urgency/action และทีมdevเชื่อมตามcontractที่อนุมัติ ถ้าออกแบบ prototype ให้แสดงข้อมูลคำเตือนที่มีแหล่งอ้างอิงโดยไม่อ้างว่าเป็นการวินิจฉัย ห้ามเขียน rules engineใหม่ในงาน UIนี้ รายการบันทึกนี้ไม่ครอบคลุมสัญญาณเตือนหลังคลอดทั้งหมด

## แชร์บันทึก

- วาง actionแชร์บนหน้าบันทึกประจำวัน/หน้าอ่าน แยกจากปุ่มบันทึก
- ลำดับ: เลือกรายวัน/สัปดาห์/เดือน/ปี → เลือกช่วงจริง → ดูpreview → เลือกว่าจะรวมnote/ชื่อหรือไม่ → สั่งแชร์เอง
- ระบุวันที่เริ่ม/จบและtimezone Bangkok; นิยามวันเริ่มสัปดาห์ให้ชัด
- บันทึกที่ไม่มีข้อมูลแสดงไม่ได้บันทึก ไม่แทนด้วย0หรือปกติ; แสดงจำนวนวันที่มีข้อมูล/ช่วงที่เลือก
- รายสัปดาห์/เดือน/ปีควรเริ่มด้วยสรุปและรายละเอียดอ้างกลับวัน ไม่ทำรายงานเหมือนมีข้อมูลครบทั้งปีทั้งที่มี3วัน หลีกเลี่ยงสรุปเชิงวินิจฉัยหรือระบุสาเหตุจากcorrelation
- ประเมินรูปแบบภาพ/PDF/ข้อความให้เหมาะกับความยาว ข้อมูลรายปียาวไม่ควรยัดเป็นภาพเดียว
- ยังไม่ส่งอัตโนมัติไปคลินิกหรือแชต การแชร์ข้อมูลสุขภาพต้องมีpreviewและการกระทำจากผู้ใช้ชัดเจน
