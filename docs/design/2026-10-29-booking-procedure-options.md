# ปรับ UI รายการหัตถการในหน้าจองคิว

วันที่: 29 ตุลาคม 2026  
Branch: `thanid-edit-main`  
หน้า: `/ruenfai/onboarding` ในขั้นจองคิวรับบริการ

## สิ่งที่เปลี่ยน

- เพิ่มภาพประกอบวงกลมขนาด 48 × 48 px ข้างชื่อหัตถการครบ 6 ประเภท โดยใช้ assets เดิมของเรือนไฟ
- ไม่แสดงกรอบหรือเปลี่ยนพื้นหลังภาพเมื่อเลือก แสดงสถานะเลือกด้วย checkbox
- แสดงข้อความ `(รอประเมิน)` ต่อท้ายชื่อโดยไม่บังคับขึ้นบรรทัดใหม่
- เปลี่ยนข้อความ `(ห้าม)` เป็น `(ห้ามทำ)` สำหรับก้อนเส้า
- คงการเลือกหลายรายการและสถานะ disabled เดิม

## การตรวจสอบ

- ตรวจภาพรายการหัตถการบนหน้าเว็บที่รันจริง และทดสอบเลือกนวดไทยกับประคบสมุนไพรพร้อมกันได้
- หลังตรวจภาพ มีการปรับตาม feedback: เอากรอบภาพที่เลือกออก และย้ายข้อความสถานะมาต่อท้ายชื่อ
- `git diff --check` ผ่าน
- `pnpm --filter @reuanfai/web typecheck` ยังไม่ผ่าน เนื่องจาก dependencies ที่ฝั่ง API หาไม่พบ ได้แก่ zod, @supabase/supabase-js, @ai-sdk/openai-compatible และ ai รวมถึง type errors ในไฟล์ API ไม่ได้แก้ dependencies หรือไฟล์ API ในงานนี้
- การจองยังเป็น browser-local demo ตามระบบเดิม

## แนวทางบันทึกงานถัดไป

ตามคำขอผู้ใช้ ให้บันทึกการแก้ไขเพิ่มเติมในไฟล์ Markdown นี้ต่อเนื่อง โดยเพิ่มหัวข้อระบุวันที่ สิ่งที่แก้ และผลตรวจ ไม่แยกไฟล์รายงานใหม่สำหรับงานต่อเนื่องใน branch นี้

## 29 ตุลาคม 2026 — เปิดบันทึกจากหน้าแรกและขยายชีตถึงขอบบน

- การ์ดบันทึกที่ทำแล้วในหน้าแรกเปิด bottom sheet ของวันที่เลือกโดยตรง ใช้ JournalForm เดิมเพื่อโหลดและแก้ไขข้อมูลวันนั้น
- ชีตบันทึกทั้งหน้าแรกและหน้าปฏิทินรองรับการขยายจนถึงขอบบน viewport เมื่อเลื่อนเนื้อหาขึ้นหรือลาก handle ขึ้น
- สาเหตุช่องว่างเดิม: shared SheetResize กำหนดความสูงสูงสุดต่ำกว่า viewport 8px และชีตบันทึกไม่ได้เปิดโหมด edge-expanded
- ปรับ CSS เฉพาะชีตที่ประกาศ edge-expanded และอยู่สถานะ expanded ให้เต็มความสูง พร้อมคลายมุมบนเมื่อเต็มจอ คง footer บันทึกและการเลื่อนเนื้อหาภายใน

## 29 ตุลาคม 2026 — ข้อความตัวอย่างบันทึกบนการ์ดหน้าแรก

- ใช้ข้อความจากช่องบันทึกเพิ่มเติมเป็นข้อความหลักบนการ์ด จำกัดไม่เกิน 2 บรรทัดและตัดส่วนเกิน
- ถ้าข้อความว่างหรือมีเพียงช่องว่าง ให้แสดงอารมณ์ พร้อมสรุปข้อมูลสุขภาพที่ระบุไว้ โดยมีชื่อข้อมูลกำกับ เช่น ความปวด อุณหภูมิ และอาการ
- ไม่แสดงช่องที่ยังไม่ได้ระบุ และไม่สร้างข้อมูลอาการขึ้นเอง บันทึกเก่าที่ไม่มีข้อมูลสุขภาพแสดงเฉพาะอารมณ์
- ข้อความฉบับเต็มและข้อมูลเดิมยังอยู่ในชีตของวันนั้น

## 29 ตุลาคม 2026 — ระยะฟอร์มบันทึกประจำวัน

- ใช้ระยะระหว่างกลุ่มคำถาม 24px และหัวข้อถึงตัวเลือก 8px ให้สม่ำเสมอ
- ยกเลิก grid gap ภายในกลุ่มที่มีช่อง conditional และใช้ระยะเฉพาะส่วนที่เปิด เพื่อไม่ให้ช่องอุณหภูมิ/คำเตือนที่ซ่อนอยู่ทิ้งช่องว่างซ้อน
- เนื้อหาที่เปิดเพิ่มยังมี animation และรองรับ reduced motion
- รวมชื่อหมวดน้ำคาวปลากับหัวข้อปริมาณเป็น “ปริมาณน้ำคาวปลา”

## 29 ตุลาคม 2026 — ปรับถ้อยคำในชีตบันทึก

- เปลี่ยนหัวข้อให้ถามตรง ๆ เช่น วันนี้รู้สึกอย่างไร และวันนี้เต้านมมีอาการอย่างไร
- ขยายคำตอบสั้นให้ระบุสิ่งที่ตอบ เช่น มีกลิ่นเหม็น/ไม่มีกลิ่นเหม็น, ปริมาณปกติ/ปริมาณมาก, เต้านมคัดตึง และแผลบวมแดง
- เพิ่มคำอธิบายระดับความปวด 0 = ไม่ปวด และ 10 = ปวดมากที่สุด
- ใช้ optionLabels แยกข้อความแสดงผลจากค่าที่บันทึก เพื่อคงบันทึกเก่าและเงื่อนไขแสดงช่อง/คำเตือนเดิม ไม่เปลี่ยนเกณฑ์ทางการแพทย์

### ผลตรวจและขอบเขตหลักฐาน

- ESLint เฉพาะไฟล์ TSX ที่แก้และ git diff --check ผ่าน
- ยังไม่ได้ยืนยันภาพจริงซ้ำหลังแก้ชุด journal เนื่องจาก browser connector แจ้ง browser.user is unavailable; อย่าถือว่า lint เป็นหลักฐาน UI ผ่าน
- ต้องตรวจต่อ: เปิดบันทึกจากหน้าแรกให้ตรงวันและข้อมูลเก่า; เปิด/ปิดช่องตำแหน่งปวด อุณหภูมิ เต้านม และคำเตือนแล้วระยะไม่สะสม; ลากชีตขึ้น/ย่อลง; footer บันทึกยังเข้าถึงได้; ข้อความยาวบนมือถือไม่ล้น
- Typecheck ทั้งโปรเจกต์ยังมี blocker ฝั่ง API ตามที่ระบุด้านบน ไม่ได้เปลี่ยน dependencies/backend ในชุดนี้
- ข้อเสนอเรื่องทำกิจกรรมแล้วจางลง/ย้ายไปท้ายรายการ และเพิ่มความเข้มวันปัจจุบัน ยังไม่ได้ implement ในชุดนี้
