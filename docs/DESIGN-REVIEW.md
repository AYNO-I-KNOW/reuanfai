# Design review — checklist ก่อน implement

> ใช้ตอนทีม design ส่งงานมา ตรวจทีละหน้าเทียบกับ `specs/screen-map.md` + checklist ใน `concept/UX-Brief_v1.pdf`
> ผลของแต่ละหน้า: ✅ ผ่าน · 🔧 ปรับ design · 📝 ต้องแก้ spec (เปิด ADR ใหม่ เจ้าของตัดสิน — ADR-0000)
> §1 ปรับตาม ADR-0014 (design ที่เจ้าของอนุมัติรอบ 1) · design ที่อนุมัติแล้วยังต้องผ่าน review ต่อ phase

## ขั้นตอน
1. สร้าง `docs/design-review/<phase>-<yyyy-mm-dd>.md` คัดลอกตารางใน §3 ไปใส่
2. ตรวจ §1 (ทั้งระบบ) ครั้งเดียว แล้วตรวจ §2 ทีละหน้า
3. ทุกช่องที่ไม่ใช่ ✅ ต้องมีหมายเหตุว่าต่างจาก spec ตรงไหน และจะแก้ที่ design หรือที่ spec
4. phase จะเริ่ม implement หน้าจอได้เมื่อทุกหน้าใน phase เป็น ✅

## 1. ทั้งระบบ (ห้ามพลาด)
- [ ] ข้อความในแชท LINE ไม่มีชื่อโรค ชื่อยา หรือผลคัดกรอง (ADR-0006)
- [ ] ไม่มีคำว่า "ปลอดภัย" ในผลคัดกรอง (ADR-0005) · ข้อความ "ไม่ใช่ผลการวินิจฉัย" ไม่บังคับ (ADR-0014)
- [ ] ปุ่ม มี / ไม่มี / ไม่แน่ใจ ขนาดเท่ากัน สีเดียวกัน และไม่ใช้สีแดง/เขียวก่อนตอบ
- [ ] ตัวเลือกที่เลือกแล้วใช้พื้น lavender ไม่ใช้สีแดงหรือเขียว (M2, M3) (ADR-0014)
- [ ] ผล M4 แสดง 3 สถานะตาม design (ทำได้ · รอการประเมิน · ห้ามหลังคลอด) มีคำกำกับ ไม่ต้องเดาจากสีอย่างเดียว · "ห้าม" **ไม่ใช่พื้นแดงทั้งกล่อง** · `not_yet` แสดงอย่างไร = SPEC Q9 (ADR-0014)
- [ ] ปุ่ม "ติดต่อด่วน" ใน bottom nav เปิด sheet (โทร 1669 + `emergencyPhone`) สูง ≥ 48px · ไม่ต้องมีทุกหน้า (ADR-0014)
- [ ] ปุ่มหลักกว้างเต็มจอและอยู่ล่างสุด (มือถือ) · หัวช่วงคำถาม 22–24px (คำถามรายข้อ 14px ได้ — ADR-0014)
- [ ] API ของผล/กฎทุกข้อคืนเหตุผล + เลขหน้าคู่มือ (ADR-0002) · จอแม่ไม่ต้องแตะดูเหตุผล (ADR-0014) · P4/audit ต้องเห็นที่มาได้
- [ ] ผลจาก AI ฝั่งกรมฯ มีป้าย "ข้อเสนอจาก AI" (ADR-0009) · ป้าย "สรุปโดย AI" บน P8 ไม่บังคับ (ADR-0014)
- [ ] ฝั่งกรมฯ มีป้าย "ข้อมูลจำลอง" และตัวเลขมี "(จำลอง)" (ADR-0012) · ฝั่งหน่วยบริการไม่บังคับ (ADR-0014)
- [ ] ฝั่งกรมฯ ช่อง n<5 แสดง "น้อยกว่า 5" (ADR-0008)
- [ ] กรมฯ ไม่เห็นข้อมูลรายแพทย์ · ฟอร์มรีวิวฝั่งแม่ไม่ถามแพทย์ · ฝั่งหน่วยบริการกรอง/ดูรายแพทย์ได้ (ADR-0014)
- [ ] ชื่อคุณแม่ฝั่งหน่วยบริการเป็นชื่อย่อเท่านั้น ("แม่ B07") ยกเว้นนัดที่ staff สร้างเอง (Q12) · การแสดงเบอร์แม่ = Q13
- [ ] ข้อมูลในเดโมเป็นข้อมูลจำลอง ไม่มีข้อมูลบุคคลจริง (ADR-0012) · ไม่ต้องมี "(ตัวอย่าง)" ต่อท้ายชื่อหน่วย/แพทย์ (ADR-0014)

## 2. ต่อหน้า — design ต้องมีข้อมูลที่ API ให้ได้ และไม่ขอสิ่งที่ API ไม่มี
สำหรับแต่ละหน้าใน screen-map ให้ตรวจ:
- [ ] **ข้อมูลครบ**: ทุก field บนจอมีใน response ของ API ที่ map ไว้ (ถ้าไม่มี → 🔧 หรือ 📝 เพิ่ม field)
- [ ] **ไม่เกิน**: ไม่มีข้อมูลที่ role นั้นไม่ควรเห็น (ARCHITECTURE §6)
- [ ] **ทุก state**: loading, empty, error, และ error code ที่ route นั้นคืนได้ (api.md) มี design ครบ เช่น M6-4 ต้องมี `quota_exhausted` "ใช้สิทธิ์ครบแล้ว หากต้องการรับบริการเพิ่ม กรุณาติดต่อหน่วยบริการค่ะ", `slot_full`, `referral_locked`
- [ ] **ข้อความตรง**: ข้อความที่ UX brief กำหนดไว้ตรงตัว (เช่น N1–N8, M4-R, M11)
- [ ] **Flow ตรง**: ปุ่มถัดไป / ย้อนกลับ / ข้าม ตรงกับ rules §2 Flow (ฟอร์มต่อช่วง ครบ 20 ข้อ ไม่ไปต่ออัตโนมัติ — ADR-0014)
- [ ] **Checklist UX brief**: ทุกข้อในหน้านั้นของ UX brief ครบ
