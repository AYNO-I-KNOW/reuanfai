# Design review — checklist ก่อน implement

> ใช้ตอนทีม design ส่งงานมา ตรวจทีละหน้าเทียบกับ `specs/screen-map.md` + checklist ใน `concept/UX-Brief_v1.pdf`
> ผลของแต่ละหน้า: ✅ ผ่าน · 🔧 ปรับ design · 📝 ต้องแก้ spec (เปิด ADR ใหม่ เจ้าของตัดสิน — ADR-0000)

## ขั้นตอน
1. สร้าง `docs/design-review/<phase>-<yyyy-mm-dd>.md` คัดลอกตารางใน §3 ไปใส่
2. ตรวจ §1 (ทั้งระบบ) ครั้งเดียว แล้วตรวจ §2 ทีละหน้า
3. ทุกช่องที่ไม่ใช่ ✅ ต้องมีหมายเหตุว่าต่างจาก spec ตรงไหน และจะแก้ที่ design หรือที่ spec
4. phase จะเริ่ม implement หน้าจอได้เมื่อทุกหน้าใน phase เป็น ✅

## 1. ทั้งระบบ (ห้ามพลาด)
- [ ] ข้อความในแชท LINE ไม่มีชื่อโรค ชื่อยา หรือผลคัดกรอง (ADR-0006)
- [ ] ไม่มีคำว่า "ปลอดภัย" ในผลคัดกรอง ต้องใช้ "ผลจากข้อมูลที่คุณแจ้ง · ไม่ใช่ผลการวินิจฉัย" (ADR-0005)
- [ ] ปุ่ม มี / ไม่มี / ไม่แน่ใจ ขนาดเท่ากัน สีเดียวกัน และไม่ใช้สีแดง/เขียวก่อนตอบ
- [ ] ตัวเลือกที่กดแล้วใช้ขอบหนาสีเข้ม ไม่ใช้สีแดงหรือเขียว (M2)
- [ ] ProcStatus 4 แบบ มีสีและคำกำกับครบ: ทำได้ในช่วงนี้ (เขียวเข้ม) · ให้ประเมินก่อน (ส้มอิฐ) · ยังไม่ถึงกำหนด + วันเริ่ม (เทา) · ห้าม (ตัวหนังสือแดงเข้ม **ไม่ใช่พื้นแดงทั้งกล่อง**)
- [ ] ทุกหน้าฝั่งแม่มีปุ่ม "ติดต่อด่วน" มุมขวาบน สูง ≥ 48px
- [ ] ปุ่มหลักกว้างเต็มจอและอยู่ล่างสุด (มือถือ) · หัวคำถาม 22–24px
- [ ] ผล/กฎทุกข้อแตะแล้วเห็นเหตุผล + เลขหน้าคู่มือ (ADR-0002)
- [ ] ผลจาก AI มีป้าย "ข้อเสนอจาก AI" / "สรุปโดย AI" (ADR-0009)
- [ ] ฝั่งหน่วยบริการ/กรมฯ มีป้าย "ข้อมูลจำลอง" และตัวเลขกรมฯ มี "(จำลอง)" (ADR-0012)
- [ ] ฝั่งกรมฯ ช่อง n<5 แสดง "น้อยกว่า 5" (ADR-0008)
- [ ] ไม่มีหน้าไหนจัดอันดับหรือให้คะแนนแพทย์รายคน
- [ ] ชื่อคุณแม่ฝั่งหน่วยบริการเป็นชื่อย่อเท่านั้น ("แม่ B07")
- [ ] ชื่อหน่วยบริการ/ยาในเดโมเป็นชื่อสมมติ ("(ตัวอย่าง)")

## 2. ต่อหน้า — design ต้องมีข้อมูลที่ API ให้ได้ และไม่ขอสิ่งที่ API ไม่มี
สำหรับแต่ละหน้าใน screen-map ให้ตรวจ:
- [ ] **ข้อมูลครบ**: ทุก field บนจอมีใน response ของ API ที่ map ไว้ (ถ้าไม่มี → 🔧 หรือ 📝 เพิ่ม field)
- [ ] **ไม่เกิน**: ไม่มีข้อมูลที่ role นั้นไม่ควรเห็น (ARCHITECTURE §6)
- [ ] **ทุก state**: loading, empty, error, และ error code ที่ route นั้นคืนได้ (api.md) มี design ครบ เช่น M6-4 ต้องมี `quota_exhausted` "ใช้สิทธิ์ครบแล้ว หากต้องการรับบริการเพิ่ม กรุณาติดต่อหน่วยบริการค่ะ", `slot_full`, `referral_locked`
- [ ] **ข้อความตรง**: ข้อความที่ UX brief กำหนดไว้ตรงตัว (เช่น N1–N8, M4-R, M11)
- [ ] **Flow ตรง**: ปุ่มถัดไป / ย้อนกลับ / ข้าม ตรงกับ rules §2 Flow (yes/no ไปต่อเลย, unsure ต้องกด "ถัดไป" เอง)
- [ ] **Checklist UX brief**: ทุกข้อในหน้านั้นของ UX brief ครบ
